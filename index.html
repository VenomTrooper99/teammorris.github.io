Assembly

Explanation of PID Controls: We kept I = 0 for all scenarios: 1. Circuit Track We selected a moderate P = 60 to provide agile steering through curves that matches our speed setting of 180. We paired this with a substantial D = 30 to act as a predictive brake, helping the robot transition smoothly between sweeping arcs and straightaways. 2. Frequency Track For the frequency track, we lowered the proportional gain to P = 40 to prevent the robot from violently overreacting since the speed is 90. Conversely, we maximized the derivative gain to D = 50 so the control loop could instantly sense the rapid rate of error change and snap the robot into alignment for the next immediate gate. 3. Drag Race Track For drag race, we minimized steering drag by dropping the proportional gain to P = 27, allowing the robot to ignore minor sensor fluctuations and focus entirely on maximum forward velocity of 255. We maintained a high D = 47 as a critical safety net to softly catch and counter-steer the robot only if it rapidly drifted off center at top speed.

Shared Code Modifications: ESP32 Dual-Core FreeRTOS Integration: Pinned the LDR analog reads to Core 0 and the PID/Motor math to Core 1. This decoupled the hardware latency. Weighted Sensor Array: Instead of treating all sensors equally, we assigned unique scaling multipliers to the LDR_Weights array (ranging from 1.0 in the center to 4.0 at the extremes). This mathematically amplifies the calculated error when the line drifts toward the outer edges, forcing an immediate, aggressive recovery response. Center-of-Mass Intersection Filter: Calculated a preliminary error using only the central 5 sensors. Based on the direction the line was leaning, the code selectively blinded the extreme opposite outer sensors to completely ignore adjacent/crossing tracks. Extreme Turn Assist: Added logic to monitor if the error goes too high. If so, it drops the forward base speed to 0, allowing the PID to forcefully drive the inner wheel backward. This pivots the robot in place, completely overcoming the physical turn-radius limits of the wheelbase. Line-Loss Memory State: When the robot encounters sharp angles or tracks that temporarily disappear, the system retains the last valid error state rather than resetting to zero. This ensures that if the line is completely lost, the motors maintain their previous turning direction to aggressively swing back onto the course instead of driving straight into a wall. Coding

The software initializes via the setup() function, which runs the Calibrate() and CalibrateHelper() functions to establish baseline black-and-white surface thresholds, before deleting the default loop() task and spawning two dedicated hardware threads. SensorThread() is pinned to Core 0 to continuously fetch and normalize sensor data via the ReadPhotoResistors() function, while PIDThread() is pinned to Core 1 to handle real-time physics and movement. Within this control thread, CalcError() calculates the line's center of mass using a weighted average and a central-sensor multiline filter, passing this spatial deviation to PID_Turn(), which calculates the necessary steering adjustments.

RunMotors() and runMotorAtSpeed() translate these adjustments into physical movement by combining them with a base speed, managing PWM constraints, deadband friction, and extreme-turn tank steering, while supplementary functions like ReadPotentiometers() and Print() handle hardware-based PID tuning and serial telemetry tracking.
